# Railway frontend

Frontend планируется как web-клиент на TypeScript и React.

Функциональная структура должна повторять пользовательские контексты API, но не
копировать серверные сущности один к одному:

```text
railway/frontend/
├── app/             # запуск приложения, маршрутизация, providers
├── shared/          # UI-kit, общие типы, HTTP-клиент и утилиты
└── features/
    ├── identity/        # вход и состояние текущего пользователя
    ├── infrastructure/  # станции, операторы и поезда
    ├── cargo/           # отправка, приём и распределение груза
    └── tracking/        # отслеживание и получение статуса груза
```

Frontend зависит от API-контрактов, а не от внутренней структуры Python
backend. Модели ответа API преобразуются в типы и view-models клиента на
границе feature-модуля.
