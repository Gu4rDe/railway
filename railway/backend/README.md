# Railway backend

Backend планируется как Python web-сервис. Структура сочетает функциональные
модули и слои:

```text
railway/backend/
├── identity/
├── infrastructure/
├── routing/
└── cargo/
```

Каждый функциональный модуль может содержать:

```text
domain/           # сущности, value objects, статусы и инварианты
application/      # use cases, команды, запросы и порты
infrastructure/  # реализации портов: БД, хеширование, внешние адаптеры
presentation/     # HTTP-маршруты, схемы API и преобразование DTO
```

## Направление зависимостей

`presentation -> application -> domain`.

`infrastructure` реализует интерфейсы, объявленные в `application`, и подключается
на уровне композиции приложения. Домен не импортирует HTTP-фреймворк, ORM,
конкретную СУБД или frontend-код.

## Модули

- `identity` — пользователи, роли, вход, выход, хеширование паролей и текущая
  сессия.
- `infrastructure` — станции, операторы и поезда как управляемые объекты
  железнодорожной инфраструктуры.
- `routing` — маршруты, последовательность станций и поиск поездов до станции
  назначения.
- `cargo` — груз, его жизненный цикл, приём, назначение на поезд, получение и
  отслеживание.

Модули не обращаются к ORM-моделям друг друга напрямую. Обмен выполняется через
порты application-слоя или устойчивые DTO/API-контракты.

Конкретные use cases, DTO, repository-порты и связи между модулями описаны в
[`../../docs/architecture/application-contracts.md`](../../docs/architecture/application-contracts.md).
